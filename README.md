# Log Academy — учебная платформа

Веб-платформа учебного центра [Log Academy](https://logacademy.az) для ведения групп, уроков, посещаемости, оценок и домашних заданий. Интерфейс на русском, азербайджанском и английском.

## Статус

Платформа в рабочей эксплуатации: используется в учебном процессе академии — педагоги ведут на ней группы и уроки, студенты получают материалы и сдают домашние задания. Развивается.

## Роли

| Роль | Возможности |
|---|---|
| **Администратор** | всё, что доступно педагогу, по всем группам; курсы, педагоги, администраторы, группы и их архив; смена пароля любому пользователю; база знаний и шаблоны курсов; статистика по педагогам; посещения платформы |
| **Педагог** | свои группы: состав, регистрация студентов и смена их паролей, расписание, уроки, материалы, посещаемость, оценки, домашние задания, квизы, видеоконференция; методические материалы |
| **Студент** | свои уроки (таблица и календарь), материалы, домашние задания, диалог с педагогом, успеваемость, заработанные звёзды в шапке кабинета |

У каждой роли — своя инструкция в разделе «Помощь» со ссылками на описанные разделы.

## Возможности

- **Группы и расписание** — генерация серии уроков по дням недели, времени и длительности; перенос урока на «выходной» со сдвигом последующих; календарь «Месяц / Неделя / День» с реальной длительностью уроков.
- **Уроки** — материалы из общей базы знаний (файлы, ссылки, квизы); урок открывается студентам по решению педагога; оценки и присутствие фиксируются в полночь дня урока (по Баку).
- **Посещаемость и оценки** — пришёл / онлайн / уважительная причина / опоздание; три оценки по шкале 0–100: за урок, за домашнее задание, экзаменационная; звёзды. Пропуск засчитывается автоматически по единому правилу для всех отчётов.
- **Домашние задания** — общие и персональные задания со сроком сдачи, ответы студентов, проверка, возврат на доработку, диалог педагога со студентом.
- **База знаний** — файлы с контролем дублей; просмотр docx / xlsx / pptx в браузере через PDF; шаблоны материалов по курсам; у каждого материала видно, в скольких уроках и в каких курсах он используется.
- **Квизы** — Flash (вопрос-ответ) и Live (игра в классе в реальном времени, вход студентов по QR-коду или коду игры, режим экзамена с оценкой в журнал); помощник собирает запрос для любого ИИ по теме и материалам урока и заполняет квиз его ответом. Квиз редактируется из Базы знаний и из урока — автором или администратором.
- **Регистрация студентов** — по ссылке или QR-коду группы, либо педагог заводит студента сам.
- **Связь с группой** — у каждой группы постоянная ссылка на видеоконференцию (Google Meet или другой сервис), Telegram и WhatsApp; три значка входа на странице группы и урока у педагога, администратора и студента.
- **Отчёты** — таблица студентов со средними оценками, пропусками и опозданиями; отчёт по ученику за месяц для родителей и отчёт по педагогу, оба с печатью; посещаемость по педагогам.
- **Посещения платформы** — кто сегодня заходил в систему и кто в ней сейчас (активен за последние 10 минут); отчёт за период по пользователям, ролям и группам: дни, первый вход, последняя активность, время в системе. Учитывается только время — без IP, браузера и открытых страниц; данные хранятся год.
- **Методические материалы** — раздел «Методика преподавания IT детям» для педагогов и администраторов: статьи по педагогике, управлению классом, планированию, методикам, оцениванию и работе с родителями.
- **Автоперевод (RU / AZ / EN)** — тексты интерфейса, включая подсказки, извлекаются из кода и переводятся автоматически; инструкции и методические материалы переводятся целиком с сохранением оформления. Единый глоссарий терминов академии, проверка качества каждого перевода, переводы хранятся вместе с исходниками.
- **Защита данных при удалении** — нельзя удалить объект, который где-то используется; система показывает, где именно.

## Логи и бэкапы

**Логи.** Ни один лог не растёт без ограничений:

| Что | Где | Ограничение |
|---|---|---|
| Контейнеры (backend, frontend, nginx) | `docker compose logs` | до 30 МБ на сервис (3 файла по 10 МБ), `docker-compose.prod.yml` |
| Попытки входа (для fail2ban) | `logs/nginx-fail2ban/login.log` | logrotate: раз в неделю или при 20 МБ, 4 архива — `deploy/logrotate/logacademy` |
| Системный журнал | journald | `SystemMaxUse=100M` |
| auditd | `/var/log/audit` | 5 файлов по 10 МБ, режим `ROTATE` |
| Кэш сборки Docker | — | `deploy-prod.sh` после выкатки урезает до 2 ГБ |

Backend пишет в stdout через `logging` (уровень INFO), без `print`.

**Нарушения CSP.** Браузеры шлют отчёты на `/api/csp-report` (`report-uri` в заголовке CSP, `deploy/nginx/prod.conf`). Они не пишутся в лог, а складываются в таблицу `csp_reports` с дедупликацией: одна строка на вид нарушения (директива + домен источника + страница с `:id` вместо id + файл:строка), повтор только увеличивает `count` и обновляет `last_seen`. Расширения браузера отбрасываются, видов — не больше 1000. Просмотр — консольная утилита `app/csp_report_list.py` на сервере, с очисткой после разбора.

**Бэкапы.** `scripts/backup.sh` (systemd-таймер `logacademy-backup.timer`, каждый день в 03:15 по Баку, от имени `quizadm`) кладёт в `/var/backups/logacademy/<дата>_<время>/`:
- `db.dump` — база (`pg_dump -Fc`);
- `minio.tar.gz` — все файлы хранилища, кроме кэша предпросмотров `previews/`.

Каждый архив проверяется сразу после записи, хранятся 14 дней. Итог каждого запуска — одна строка `OK` / `FAIL` / `SKIP` в `/var/backups/logacademy/backup.log`. Пока бэкапы лежат на том же сервере — перенос на отдельный сервер / S3 запланирован. Установка и восстановление — `DEPLOYMENT.md`.
